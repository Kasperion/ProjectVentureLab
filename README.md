# Project Venture Lab

A text-focused solo fantasy game, beginning with a challenge to recover a wedding ring from a dragon's hoard.

**Working encounter title:** A Ring in the Hoard. The overall product title is still open.

The first encounter is intended to offer a memorable character, discoverable evidence, several credible approaches, and a clear outcome. AI supports freeform dialogue; authored facts and game rules keep consequences consistent.

## Current status

This repository contains the project documentation. The encounter is a draft ready for review and manual rehearsal; a runnable game has not been implemented.

The founder has chosen to continue the dragon game. The discussion of The Citadel of Thorns was research and inspiration, not approval to change the project into a roguelite.

## Approved direction

- Solo play first, followed by paid content packs.
- A possible group or party expansion later.
- Text-focused presentation with limited still artwork.
- First challenge: recover a wedding ring from a dragon's hoard.
- A solo-founder project suitable for a beginner programmer.
- Approximately $100–$200 per month for development and testing.
- This repository may remain public, as authorized on November 2, 2026.

Browser-first delivery is the recorded project preference. Prices, pack sizes, replay allowances, technology, model, and art style remain open. Orryx, the couple's names, the backstory, and the detailed rules are proposed design choices.

## First playable target

The proposed prototype has one location, one main character, typed input, access to the couple's letter, a notebook of confirmed discoveries, and a clear ending. A 10–20 minute first attempt is a design target; a valid early solution should succeed promptly.

The game should support several reasonable approaches while preserving established facts. Claiming to possess the ring does not award it. An accepted bargain needs clear terms, player consent, and actual fulfillment.

## Next steps

1. Review the draft encounter's tone, resistance, and routes to success.
2. Rehearse one complete playthrough and record confusing or unfair outcomes.
3. Revise the design, then test it with a small number of independent players.
4. Select a simple implementation approach for one browser encounter.
5. Measure completion, replay, AI usage, and interest in a paid follow-up before expanding.

Use the [playtest plan](docs/dragon-game/playtest-plan.md) for the immediate work. No installation or run command exists yet.

## Commercial hypothesis

Players would pay for crafted, playable encounters with satisfying characters, consistent consequences, and worthwhile new situations. Paid demand and repeat purchasing remain unvalidated.

One complete free introductory encounter followed by paid packs is a proposal. Pricing and included AI usage should follow testing of enjoyment, production effort, and operating cost.
